# UX Designerレビュー（2026-11-10）

対象：ローカルSmart Home Dashboard。iPad Air 5横画面1180×820を主対象。レトロ表現、NES.css、DotGothic16、アイコンのみのタブ、家電のみカラーというユーザー指定を維持する前提。

## 優先度順の指摘

1. Major：小画面で操作領域と文字が縮小される。320×740ではtransform scale=0.3125、追加・全画面ボタンは実測13.75×13.75px。14pxのラベルも見かけ上4.375px。app.js:161 fitViewport。全体縮小ではなく、狭幅時は1列または要約表示へ再配置し、操作領域44pxを確保する。iPad横1180×820では同ボタン44px。
2. Major：画面外のページがキーボード移動・読み上げ対象に残る。ホームの掃除機詳細ボタンからTabすると、家電操作ページのdevice-ac-toggleへ移り、矩形x=1216、幅48で画面外。各.pageにinert/aria-hiddenがない。非表示ページをinertにし、切り替え時に選択画面だけ解除する。見えないフォーカスを防ぐ。
3. Major：通知が設定操作の途中経過で埋まる。履歴に同一時刻の23℃通知が3件、その後22〜16℃等が連続。app.js:46 range inputごとsave→syncNotifications。履歴だけでは発生時の操作を断定できないが、コードは入力ごとの通知を許す。値表示はinput、確定通知はchangeまたは操作終了後の集約にする。
4. Minor：家電欄のサーキュレーターが単語途中で2行になる。固定224px列にアイコン・名前・ON/OFFを詰めている。styles.css:269,315,339。名称は一行を基本に、バッジを状態行へ移すなど内側の列配分を調整する。左右枠を同幅にする仕様は維持。
5. Minor：16×16の家電アイコンはiPad横でも実表示16pxで、空気清浄機等の形が読み取りにくい。styles.css:375。元絵は16×16のまま、UIでは32×32の整数倍率を検討し、名称も併記し続ける。
6. Minor：メディア画面の未再生時に「このPCの再生情報」が重複し、再生ボタンが無効な理由が画面上で分からない。再生メタデータ取得のみの現実に合わせ、「PCで音楽を再生すると表示」等の短い空状態を出し、操作未対応をボタン付近で示す。既存のレコード表現は維持。

## 確認範囲と制限

ローカルブラウザーでホーム、予定追加ダイアログ、エンタメ、カレンダー、通知を目視。1180×820と320×740で比較し、実寸・フォーカスをDOMで測定。予定や家電値、通知の既読状態は変更していない。画面サイズを元に戻した。iPad Safari実機、200%ズーム、長文・大量予定・通信遅延・エラーの注入は未実施。axe/Lighthouseはプロジェクトに導入されておらず未実施で、アクセシビリティ適合を断定するレビューではない。アプリ実装・Sitesは変更なし。
